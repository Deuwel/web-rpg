# RE:RPG 개발 가이드라인

버전 v0.2 | 기준일 2026-11-06

이 문서는 [게임 기획서](GAME_DESIGN.md)를 코드와 화면에 일관되게 구현하기 위한 기준이다. 규칙의 의미와 콘텐츠는 기획서를 기준으로 하고, 본 문서는 구현 방법, 데이터 경계, 검증과 변경 절차를 정의한다.

## 1. 작업 시작과 변경 원칙

1. 변경할 기능에 해당하는 기획 절과 미정 항목을 확인한다.
2. 확정 규칙, 채택된 초기 밸런스, 미정 정책을 구분한다.
3. 관련 코어와 데이터를 먼저 확인하고 공통 계산을 재사용한다.
4. 사용자가 승인한 범위 안에서 구현하며 새로운 규칙은 제안으로 남긴다.
5. 실제 진입점에서 작동을 검증하고 문서와 코드의 차이를 정리한다.

밸런스 수치 변경은 이전 값, 새 값, 이유, 영향받는 빌드를 기록한다. 초기화와 보존, 장비 소모, 자원 정산, 클래스 강화 자격의 변경은 규칙 변경으로 취급한다. 저장 형식이 달라지면 마이그레이션 계획을 함께 기록한다.

우선순위는 사용자의 최신 명시적 결정 → 기획서의 확정 규칙 → 채택 초안 → 구현 제안 순서다. 구현 편의를 이유로 10번째 던전의 회귀 조건, 기본 자동 스킬, 마스터리 보존 등을 바꾸지 않는다.

미정 규칙을 구현할 필요가 있으면 변경 제안에 임시값과 영향을 명시한다. 중요한 프레스티지 초기화 정책은 UI가 약속하기 전에 확정한다. 무관한 기능 작업은 해당 결정을 기다리지 않고 진행할 수 있다.

## 2. 구조와 책임

웹 표준 HTML / CSS / JavaScript를 기본 방향으로 둔다. 구체적인 빌드 도구와 프레임워크는 구현 시 선택하고 의존성을 최소화한다. 로직과 데이터는 렌더러에서 독립시킨다.

다음은 책임 분리를 위한 디렉터리 제안이다. 실제 파일을 미리 생성하거나 빈 추상 계층을 만드는 요구는 아니다.

| 영역 | 책임 |
|---|---|
| core/combat | 게이지, 행동 큐, 피해와 보호막, 상태이상, 사망 |
| core/tactics | 후보 검증, 조건 평가, 우선순위, 슬롯 순서 |
| core/character | 레벨, 경험치, 포인트 투자, 클래스 선택 |
| core/skills / personas | 습득과 사용 자격, 강화, 고유 상태와 이벤트 |
| core/equipment | 템플릿과 인스턴스, 장착, 품질과 능력치 |
| core/crafting | 강화, 재련, 옵션 재설정과 줄 잠금 |
| core/inventory / economy | 보유, 잠금, 매각, 분해, 비용 지불 |
| core/progression | 마을, 던전, 보스, 조건별 해금 |
| core/prestige | 회차 누계, 보상 미리보기, 초기화와 보존 |
| core/mastery | 타입별 숙련도와 영구 보너스 |
| core/rewards | 적 개체별 보상 확정과 중복 방지 |
| core/summary | 캐릭터와 재화, 능력치 출처의 공통 조회 결과 |
| data | 장비, 스킬, 적, 지역, 비용, 배율, 트리와 노드 |
| ui / effects | 입력, DOM, 반응형, 네온과 전투 연출 |
| storage | 직렬화, 검증, 저장, 복원, 이전 버전 변환 |

수치와 드롭률, 비용표, 조건, 타격 수를 UI 코드에 흩뿌리지 않는다. 전투와 장비 비교, 캐릭터 창, 대장간은 같은 코어 계산 결과를 사용한다. 화면 이름은 번역 가능한 표시 문자열로, 내부 연결은 안정적인 ID로 관리한다.

Everkin의 공통 요약과 개체별 보상 구조를 참고할 수 있다. 코드를 재사용하기 전에 RE:RPG의 9슬롯, 품질, 포인트, 전술, 프레스티지 규칙과 맞는지 확인한다. 기존 프로젝트의 UI, 직업 제한, 티어 수치, 초기화 정책을 자동으로 가져오지 않는다.

## 3. 상태와 데이터 계약

### 3.1 장비

개별 장비에는 최소한 아래 정보를 둔다.

| 필드 | 내용 |
|---|---|
| instanceId | 획득 개체의 고유 ID |
| templateId | 장비 원형 |
| requiredLevel / rarity | 레벨 제한과 장비 등급 |
| quality / enhancementLevel | 0~100 품질과 일반 0~9 강화 |
| affixes | 안정적인 줄 ID, 옵션 ID, 수치 |
| affixLocks | 재설정에서 보존하는 줄 |
| protected | 매각과 분해 방지 잠금 |
| sockets / runes | 후속 소켓과 룬의 소유 관계 |
| location | 장착, 인벤토리, 임시 획득함, 공허 창고 중 한 위치 |

최종 능력치는 원형, 레벨, 등급, 품질, 강화, 옵션을 통해 계산한다. 저장한 최종값을 다시 강화 기준으로 삼아 복리 증가를 만들지 않는다. 캐시를 쓰면 입력 변경 시 무효화한다.

보조무기 활성화와 양손 점유는 장착 트랜잭션에서 검증한다. 슬롯 이동에 실패하면 아이템과 장비 상태를 원래대로 유지한다.

### 3.2 캐릭터와 영구 성장

스탯 포인트는 지급 누계, 투자량, 남은 포인트의 관계를 검증한다. 스킬 포인트도 습득 비용과 환급이 보존되어야 한다. 메인과 서브가 같아도 같은 스킬의 비용과 패시브를 두 번 적용하지 않는다.

현재 클래스, 현재 페르소나, 배운 스킬, 강화 수준, 전술 슬롯, 조건을 구분한다. 메인 클래스 변경 후 기존 스킬 강화가 비활성화되는지 또는 환급되는지는 별도 정책으로 확정한다. 서브로만 존재하는 클래스의 스킬을 새로 강화하는 것은 차단한다.

마스터리 레벨과 경험치는 영구 상태 영역에 둔다. 장비와 현재 회차를 초기화하는 루틴이 이 영역을 함께 지우지 않도록 한다.

### 3.3 프레스티지

잔액과 누계를 독립 필드로 둔다. 예를 들어 환생 회차의 시간 파편 획득 누계는 시간 파편을 지출해도 유지한다. 회귀 실행 때 누계를 갱신하고 환생 경계에서 새 회차를 시작한다.

에테르 누계의 L3 회차 범위는 미정이므로 회차 ID와 정산 기록을 보존할 구조를 마련한다. 마지막 환생 이후 에테르만 남기도록 임의 구현하지 않는다.

공허 창고 아이템은 다른 위치와 동시 소유하지 않는다. 회귀 보존 업그레이드, 환생 창고 보존, 장비 잠금은 각각 독립된 정책이다. 초기화 미리보기와 실제 실행은 같은 정책 함수를 사용한다.

## 4. 전투 시뮬레이션

### 4.1 시간과 이벤트

전투 시간과 화면 프레임을 분리한다. 고정 간격 시뮬레이션 또는 다음 이벤트 시각 기반 처리를 사용하고 프레임 수로 공격 횟수를 결정하지 않는다.

일반 행동의 게이지 도달 시점, 지속 피해, 회복, 버프 종료, 포션 재사용 시점을 동일 전투 시간 축에서 처리한다. 일시정지 시 시뮬레이션을 멈추며 복귀한 실제 시간 전체를 임의로 따라잡지 않는다.

동시 도달은 플레이어 우선과 적의 고정 순서를 따른다. 하나의 사건을 완결한 뒤 다음 사건으로 넘어간다. 행동 도중 사망한 대상, 전투 종료, 웨이브 교체 후 오래된 콜백이 새 대상에 피해를 주지 않도록 전투 ID와 개체 ID를 검증한다.

스킬 쿨타임은 초 또는 자기 차례 수를 명시한다. 기존 초안은 자기 차례 수를 기준으로 제안했으며 최종 선택은 미정이다. 추가 행동이 차례 쿨타임을 줄이는지, 영창의 준비 차례가 포함되는지도 같은 표에 정의한다. 포션 쿨타임은 종류별 전투 시간 기준 초 단위로 제안한다.

### 4.2 전술 선택

정렬 키는 다음과 같다.

`(우선순위 오름차순, 조건 만족 스킬 우선, 슬롯 인덱스 오름차순)`

조건 미충족 스킬과 자원 부족, 무기 불일치, 미습득, 쿨타임 중인 스킬은 정렬 전에 제외한다. 조건부 우선은 같은 우선순위 그룹 안에서만 적용한다.

예약 스킬, 자동 전술, 기본 공격, 페르소나의 준비 / 발동 행동 사이의 실행 순서는 데이터와 테스트로 고정한다. 비용은 실제 실행 확정 시 한 번 차감한다. 도중에 대상이 사라지면 재선택 또는 취소 정책을 스킬별로 명시한다.

### 4.3 타격과 자원

쌍수의 두 타격은 한 행동에 묶되 타격별 치명타와 온힛 결과를 기록한다. 일반 쌍수의 첫 타격 처치 시 두 번째 타격을 다른 적으로 옮기지 않는다. 페르소나의 명시적 피해 이전은 별도 효과다.

실제 HP 손실, 보호막 흡수, 초과 피해, 유효 회복, 초과 회복을 분리한다. 흡혈은 해당 타격의 인정 피해를 기준으로 계산한다. 보호막에 준 피해의 흡혈 인정 여부는 명시적으로 결정한다.

물리와 마법의 복합 피해는 성분별 방어 적용 후 합친다. 마탄사나 마검사가 두 공격력을 사용할 때 두 성분에 전체 합계를 중복 적용하지 않는다.

전투 난수, 드롭 난수, 재련과 재설정 난수, 시각 효과용 난수를 구분한다. 입자 수나 화면 크기가 전투 결과를 바꾸면 안 된다.

### 4.4 페르소나 이벤트

효과 이벤트에 전투 ID, 원인 이벤트 ID, 시전자, 대상, 원본 스킬, 실행 출처, 중첩 깊이를 기록하는 구조를 권장한다.

| 효과 | 반드시 정의할 항목 |
|---|---|
| 폭주 | 진입, 만료, 연장 상한, 단일 공격의 전체화 대상 |
| 교차 재현 / 그림자 | 원본 시전 인정 기준, 복제 계수, 자원과 쿨타임, 재귀 제한 |
| 추가 행동 | 처치 또는 피해 이정표의 고유 ID, 지급과 소비, 연쇄 종료 |
| 죽음의 유예 | HP 0의 생존 상태, 생존량 계산, 만료 시 사망, 치명 피해 생존 패시브와 순서 |
| 지연 피해 | 적립, 시간별 적용, 회복 정산, 응징 전환과 소비 |
| 영창 / 조준 | 준비 차례, 취소, 조기 발동, 전투 종료와 대상 사망 처리 |
| 주문 탄창 | 순서, 용량, 주문 스냅샷 여부, 쌍수의 탄약 소비 수 |
| 자원 교환 | 태세, 최소 생존 HP, 자원 부족 시 대체 행동 |
| 독 전파 | 남은 피해와 지속시간, 대상 수 배분, 중복 전파와 보스 정산 |
| 선고 | 기록 대상, 기록 배율, 집행 소비, 집행 피해의 재적립 여부 |
| 시간 절단 | 적 게이지와 지속 효과의 정지 범위, 타격 기록, 종료 일괄 정산 |
| 성흔 전가 | 자가 효과 출처, 정화 순서, 전가량, 면역과 대상 사망 |
| 기적 | 실제 회복과 흡수의 은총, 초과 회복, 전환 공격의 재발동 제한 |

생환 성공 전에는 광전사에게 패배 보상을 확정하지 않는다. 반대로 유예 만료 후 시각 효과가 남아 있다고 생존 판정을 늦추지 않는다.

각 효과는 명시된 허용 경로만 다른 효과를 발동한다. 복제 시전이 복제를 생성하거나 회복 피해가 다시 회복 전환을 무한 생성하지 않게 한다. 이벤트 처리 상한은 오류 복구용으로 두고 합법적인 추가 행동을 임의로 잘라내는 밸런스 규칙으로 사용하지 않는다.

## 5. 경제 변경과 저장의 일관성

강화, 재련, 재설정, 매각, 분해, 장착, 창고 이동, 프레스티지는 다음 흐름으로 처리한다.

1. 현재 상태와 대상 소유권, 비용, 요구 조건을 확인한다.
2. 미리보기와 일치하는 현재 규칙 버전을 사용한다.
3. 비용과 대상 아이템, 결과를 한 번에 적용한다.
4. 정상 상태를 저장한 뒤 결과 이벤트를 표시한다.
5. 실패 시 자원 차감이나 아이템 이동만 남는 중간 상태를 제거한다.

연속 클릭, 중복 요청, 새로고침으로 같은 소비와 지급이 반복되지 않게 작업 ID와 저장 버전을 활용한다. 난수 결과를 새로고침마다 재추첨해 비용 없이 결과를 바꾸는 경로를 만들지 않는다.

강화석 분해량은 강화 단계와 레벨 제한, 등급을 받아 계산하는 공통 함수로 제공한다. 강화 또는 재련 UI에서 비용을 별도로 계산하지 않는다.

기본 재련과 고급 재련의 품질 변화는 퍼센트포인트다. 잠재능력 줄 잠금은 해당 줄의 ID와 값을 보존하고 잠그지 않은 줄만 교체한다. 동일 등급 재료 장비를 고급 재련에 쓸 때 재료와 대상 ID가 같거나 이미 소비된 장비면 실행을 거절한다.

처치 보상은 전투 개체 ID에 연결한다. 동시 다수 처치, 재현, 다단 타격, 불러오기에도 경험치와 아이템을 한 번만 지급한다.

## 6. 큰 수와 계산 정확성

L4는 시간 파편 1e308과 에테르 1e30을 요구한다. 생산과 곱연산은 그보다 큰 값을 만들 수 있으므로 자원과 성장 수치에 일반 부동소수점만 의존하지 않는다. 큰 수 전용 표현과 비교 / 합산 / 곱셈 / 직렬화 인터페이스를 마련하고 구현 시 적합한 라이브러리를 선택한다.

선택 전에 아래 항목을 검증한다.

- 1e308과 그 이후 값을 유한한 상태로 계산하고 저장할 수 있는가.
- 문턱 바로 아래 / 같음 / 위의 비교가 정밀도 정책에 맞는가.
- 작은 보상을 매우 큰 잔액에 더했을 때 보존 또는 손실 규칙이 명시되어 있는가.
- 지수와 가수 표현을 JSON으로 안전하게 왕복할 수 있는가.
- 전체 표시와 축약 표시가 같은 계산값을 참조하는가.

정수 개수, 확률, 시간, 표시값의 자료형을 구별한다. NaN, 무한대, 음수 잔액을 정상 저장으로 확정하지 않는다. 강화 계산의 소수점은 최종 정수화까지 유지한다.

매우 큰 수에서 모든 1단위 증가를 보존할지, 유효 자릿수 기반으로 근사할지는 OPEN-13에서 결정한다. 전체 숫자 표시는 계산 정밀도를 초과하는 정확성을 약속하지 않도록 도움말과 형식을 정한다.

## 7. 네온 UI 가이드

### 7.1 시각 체계

승인된 방향은 **어두운 배경, 명확한 기본 도형, 절제된 네온**이다. The Tower는 분위기 참고이며 RE:RPG의 정보 구조를 유지한다.

| 역할 | 색 제안 | 사용 |
|---|---|---|
| 기본 배경 | #0B1018 | 전장과 화면 바탕 |
| 패널 | #121B28 | 정보 영역 |
| 본문 | #E7F0F7 | 숫자와 주요 정보 |
| 보조 글자 | #A9B8C8 | 설명과 부가 정보 |
| 플레이어 / 회복 | #79E5C9 | 플레이어 도형과 회복 |
| MP | #7CB8FF | 마나 |
| 적 / 피해 | #FFAD8E | 적 상태와 피해 |
| 행동 / 경고 | #E6D47C | 행동 게이지와 예고 |
| 특수 효과 | #C9B4FA | 영체와 일부 페르소나 효과 |

색은 출발값이다. 본문 대비와 실제 기기 가독성을 확인한다. 글로우는 공격, 선택, 발동에 집중하고 모든 텍스트와 테두리에 상시 과도하게 적용하지 않는다.

전장 도형은 CSS border, border-radius, clip-path, transform, gradient와 pseudo-element로 만든다. 배경과 게이지, 재화 아이콘도 CSS로 구성한다. 이미지 다운로드가 필요한 UI를 기본값으로 만들지 않는다.

형태, 이름, 진행률 또는 상태 텍스트로 의미를 함께 제공한다. 적 종류는 실루엣, 크기, 선 형태로 구별하고 색만으로 식별하게 하지 않는다.

### 7.2 텍스트와 재화

- 두 텍스트를 연결할 때 기본 구분자는 `|`다.
- 재화 항목에는 구분자 대신 **아이콘 + 보유량 + 항목 사이 여백**을 사용한다.
- 골드, 강화석, 혼돈 파편은 전투 중 고정된 요약 영역에서 계속 확인할 수 있다.
- 추가 프레스티지 재화는 현재 단계와 관련된 항목을 확인 가능한 위치에 배치한다.
- 재화 아이콘의 접근 가능한 이름을 제공하고 탭 또는 포커스로 설명을 연다.
- 수치 축약은 기본 OFF이며 설정을 저장한다.
- 닉네임은 사용자가 정한다. UI 렌더링에서 HTML로 해석하지 않고 텍스트로 삽입한다.
- 닉네임 길이 제한은 기존 시연의 16자를 제품 확정값으로 자동 승계하지 말고 입력 정책을 정한다.
- 정지 버튼 이름은 일시정지다.

### 7.3 반응형과 접근성

데스크톱에서는 전장과 전술, 전투 기록을 함께 보여줄 수 있다. 모바일에서는 전장과 생존 정보, 재화, 포션, 정지 조작을 우선하고 상세 패널은 필요할 때 연다.

360 / 390 / 768 / 1440 CSS px 폭에서 확인한다. 적 1명, 2명, 3명, 긴 닉네임, 높은 자원 수치, 스킬 효과 집중 상태를 포함한다. 가로 스크롤에 의존하는 기본 전투 화면을 만들지 않는다.

주요 터치 영역은 44×44 CSS px 이상으로 한다. 브라우저 안전 영역과 모바일 키보드에 버튼이 가려지지 않게 한다. 포커스 표시, 키보드 조작, 명확한 버튼 이름, 터치로 여는 설명을 제공한다.

전투 로그의 모든 틱을 스크린리더 알림으로 내보내지 않는다. 중요한 결과만 알리고 상세 로그는 읽을 수 있게 한다. reduced-motion을 존중하며 흔들림과 입자를 줄여도 숫자와 결과는 유지한다.

### 7.4 연출과 성능

피격은 대상에 연결되고 데미지 수치는 해당 개체를 따라야 한다. 여러 적을 맞히면 각 대상의 피해를 구별한다. 실제 HP는 즉시 반영하고 잔상은 시각용으로만 지연한다.

안정적인 전투 DOM을 유지하고 틱마다 전체 패널을 다시 생성하지 않는다. 일시 효과는 종료 이벤트와 안전 타임아웃으로 정리하고 동시에 표시할 수를 제한한다.

60fps 데스크톱, 선정한 보급형 모바일 30fps 이상을 목표로 실제 기기와 브라우저에서 측정한다. 효과 변경이 드롭 결과나 전투 시계에 영향을 주지 않는지 확인한다.

## 8. 저장과 불러오기

- 버전이 있는 저장 스키마와 이전 버전 변환을 제공한다.
- 현재 저장과 이전 정상 저장의 백업을 보존한다.
- JSON 가져오기는 검증을 통과한 뒤 적용하며 실패 시 기존 상태를 보존한다.
- 정기 저장과 함께 장비 획득, 정비, 레벨업, 보스 클리어, 프레스티지 등 중요한 변경 후 저장한다.
- 전투 복원은 현재 적과 게이지, 버프, 쿨타임, 미정산 효과와 고유 상태를 복원한 뒤 일시정지로 시작하는 안을 사용한다.
- 미정산 선고, 지연 피해, 탄창, 조준, 영창, 시간 절단의 기록을 빠뜨리지 않는다.
- 새로고침으로 재화나 마스터리를 중복 획득하지 않는다.
- 여러 탭의 동시 저장 충돌을 막고 활성 플레이 탭을 관리한다.
- 초기 동기화는 JSON 내보내기 / 가져오기로 제공한다. 계정 동기화 도입은 별도 범위다.

프레스티지 정산은 실행 ID, 이전 회차, 새 회차, 보상과 보존 결과를 갖는 하나의 완료 단위로 저장한다. 미리보기에 나온 아이템이 초기화 후 실제 위치와 일치해야 한다.

## 10. 문서와 작업 완료

기획 수정은 GAME_DESIGN.md에 규칙과 상태를 반영하고 본 문서에 구현과 검증 영향을 반영한다. 세부 데이터 표를 분리하게 되면 기준값의 소유 문서를 하나로 정한다.

작업 완료 보고에는 바뀐 사용자 동작, 검증한 경로, 남은 제한, 관련 커밋을 포함한다. 실제로 실행하지 않은 테스트를 통과했다고 보고하지 않는다. 화면 변경은 데스크톱과 모바일에서 확인하고 대표 장면을 남긴다.

문서 작업만 한 경우 코드 기능을 구현한 것으로 표시하지 않는다. 구현되지 않은 프레스티지와 스킬은 사용자에게 작동 가능한 버튼처럼 노출하지 않는다.

## 11. 이번 문서화의 결정 상태

- 사용자 승인으로 네온 도형 전장, 직업과 페르소나 구조, 파격적인 고유 효과를 개발 방향으로 채택했다.
- 강화의 +5% 시작, 단계별 상승폭 증가, 상위 등급 강화 효율은 반영했다. 1%p 단계 증가와 등급 배율은 조정 가능한 초기값이다.
- 페르소나 6개 스킬의 재구성 표는 이번 고유 효과와 기존 스킬안을 연결한 제안이다.
- L2 / L3의 초기화 범위와 개변 반복 조건, 보존 장비의 저레벨 사용 여부 등은 기획서 OPEN 목록에서 추적한다.
- 이 문서화는 게임 코드 배포나 기존 프로토타입의 기능 갱신을 의미하지 않는다.
